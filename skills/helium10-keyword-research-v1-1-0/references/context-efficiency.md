# 上下文与 Token 效率

## 目标

在不降低数据完整性、分页覆盖和工作簿验证强度的前提下，减少模型调用次数与重复上下文。Token 优化只改变执行编排，不改变 Helium 10 数据口径、自然排名阈值或输出结构。

## 何时建议新对话

满足任一条件时，在开始取数前只建议一次：

1. 当前对话已经完成过另一轮 Helium 10 调研。
2. 当前对话出现过大段日志、JSON、CSV、文档或与本任务无关的长历史。
3. 运行环境直接显示单次模型调用正在反复处理很大的历史输入。

新对话的含义是创建一个新的 Codex 对话，由用户粘贴最小启动模板后运行。Skill 本身不能把正在执行的任务自动搬到新对话；没有用户明确要求时也不得擅自创建线程。

如果用户选择留在当前对话，立即继续执行，并使用下方批处理策略。新对话建议不得成为 `ASK`、`PARTIAL` 或 `BLOCKED` 的原因。

## 最少往返策略

1. 一次校验全部 ASIN、站点和变体口径。
2. 第一个 ASIN 单独取首屏以建立插件 `session_id`。
3. 取得会话标识后，在插件允许时，把其余 ASIN 首屏放入同一并行工具批次。
4. 汇总所有 `has_more` 和 `next_cursor`，在插件允许时按轮次并行续页。
5. 每个下载链接收到后立即落盘；会话只保留路径、行数、字段、分页状态和 notice 摘要。
6. 所有源文件就绪后，只做一次字段/行数聚合检查、一次工作簿构建、一次读回验证。
7. 最终只回传状态、统计、绝对产物路径、限制和运行效率收据。

并行失败、插件限流或共享会话要求串行时，退回串行。不得减少 ASIN、忽略续页、跳过失败项或隐藏 `PARTIAL/BLOCKED` 来换取更低 Token。

## 大结果边界

- CSV 和完整 JSON 必须写入本次任务目录，不进入模型上下文。
- 单次工具输出预计过大时，只保留字段白名单和聚合统计。
- 不重复打开已经校验且未发生变化的 Skill、CSV 或收据。
- 不读取其他 Helium 10 Skill、历史业务 Skill 或上一轮输出作为本轮隐式输入。

## 用量报告

只有运行环境直接提供本轮 usage 时才报告：

```text
TOKEN_USAGE input=<n> cached_input=<n> output=<n> total=<n> source=runtime_best_effort
```

其中缓存输入包含在输入 Token 中，推理 Token 包含在输出 Token 中，不能重复相加。没有直接用量时输出：

```text
TOKEN_USAGE=NOT_AVAILABLE
```

不得为了得到这个数字额外扫描整段 rollout，也不得根据文件行数、账户额度百分比或主观感觉估算本轮 Token。
